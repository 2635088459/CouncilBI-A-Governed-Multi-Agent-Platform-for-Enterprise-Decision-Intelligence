# 00 总体提交版系统设计

## 1. 项目定位

本项目是一个面向企业决策智能的 Governed Multi-Agent ChatBI Platform。它不是普通聊天机器人，也不是只会生成 SQL 的 Demo，而是一个把自然语言问答、业务语义层、SQL 安全治理、RAG 证据解释、分析预测、评估发布门禁和可观测性放在一起的企业级数据问答平台。

用大白话讲：用户可以像问同事一样问业务问题，系统负责把问题拆成查询、分析、解释、验证几个步骤，最后给出可追踪、可解释、可审计的答案。

## 2. 最终提交版要证明什么

最终版本不是只证明“我能调大模型”。它要证明下面几件事：

1. 系统能服务不同用户，而不是只有本地单人使用。
2. 系统能接入真实大模型，但不会把所有逻辑都交给 prompt。
3. 系统有安全边界，危险 SQL、越权数据和敏感字段不会随便暴露。
4. 系统有可观测性，出错后能知道是哪一步慢、哪一步错、哪一步质量下降。
5. 系统有评估和发布门禁，不能靠主观感觉判断“这版好不好”。
6. 系统能部署到云端，有 Kubernetes、Secret、扩缩容和基本韧性设计。

## 3. 当前 MVP 能力

当前代码和文档已经覆盖：

1. ChatBI API 和应用入口。
2. Orchestrator 与多 Agent 协作框架。
3. SQL Guardrail 和治理审计基础。
4. RAG worker/service/indexing 的初始结构。
5. 分析和预测模块。
6. 评估、trace、metrics、release gate、observability dashboard 的后端能力。
7. README 和 v2 系统设计文档。

这些能力说明系统的“骨架”已经有了。

## 4. 最终版本缺口

现在离工业级提交还差这些“硬工程能力”：

1. Auth：用户注册、登录、token、session、密码安全。
2. RBAC：普通用户、分析师、管理员的权限分离。
3. Tenant Isolation：不同组织的数据、审计、文档不能混在一起。
4. LLM Gateway：统一封装大模型 API，不让业务代码直接依赖某一家 Provider。
5. Embedding + Vector DB：让 RAG 变成真实检索系统。
6. Admin Console：评估、trace、审计和安全事件只能管理员看。
7. Data Seed：生成大量业务数据、文档数据、评估数据和压测数据。
8. Resilience：熔断、限流、重试、超时、队列、降级。
9. Cloud/Kubernetes：云端部署、Ingress、TLS、Secret、HPA、CI/CD。

## 5. 最终架构原则

### 原则一：大模型是能力，不是系统边界

大模型负责理解、生成和总结，但权限、安全、审计、指标口径必须由后端系统控制。这样即使模型出错，系统也不会失控。

### 原则二：所有关键动作都要可追踪

一个用户问题至少要能追踪到：

1. 谁问的。
2. 属于哪个组织。
3. 调用了哪些 Agent。
4. 生成了什么 SQL。
5. SQL 是否被 Guardrail 放行。
6. 调用了哪个模型。
7. 花了多少 token 和成本。
8. 最终结果是否通过评估或验证。

### 原则三：普通用户和管理员视角必须分开

普通用户只看到自己的查询、答案和允许访问的数据。管理员才能看到全局 trace、release gate、质量指标、审计日志、安全事件和系统健康状态。

### 原则四：先把边界搭牢，再优化智能效果

工业项目里，权限、数据隔离、审计、部署、回滚这些能力不比模型效果低级。它们决定系统能不能真的上线。

## 6. 最终提交形态

最终项目应该包含：

1. 可本地启动的 Docker Compose 环境。
2. 可部署的 Kubernetes manifests 或 Helm chart。
3. 可配置的大模型 Provider。
4. 可配置的 embedding/vector backend。
5. 可重复生成的测试数据和评估数据。
6. API 文档和系统设计文档。
7. 一键运行的测试、评估和 release gate。
8. 面向用户和管理员的演示路径。

## 7. 老师式总结

如果把项目比作一家公司里的数据分析团队：

1. Orchestrator 是项目经理，决定谁来干活。
2. SQL Agent 是数据分析师，负责查数。
3. RAG Agent 是资料管理员，负责找业务文档和证据。
4. Verifier 是质检员，负责检查答案靠不靠谱。
5. Guardrail 是安全主管，负责挡住危险操作。
6. Observability 是监控室，负责记录全过程。
7. Auth/RBAC 是门禁系统，决定谁能进哪个房间。
8. Kubernetes 是办公楼和调度系统，负责让服务稳定运行。
